## 1. 症状 — 同じ勝率、146点差

```
              ラダー   Alakazam    lucario_ex   ミラー      全体勝率
```

**勝率は同一 0.537。** 差は「誰に勝っているか」で、v046 はより弱い相手に同じ勝率しか出せていない。
TrueSkill は勝率5割になる高さで落ち着くので、これは v046 が実際に下の層にいることを意味する。

## 2. 真因 — ゲートが自己ミラーだった

`gate.py` / `eval_cross.py` は両席とも `grimmsnarl_deck.json`。
つまり n=400 の 0.608 は **「ミラーが強くなったか」しか測っていない**。
そして 15日コーパスは **46%がミラー戦**。ミラーに特化してフィールドを失う劣化は、
**この設計では原理的に観測不能**だった。

これは過去3回の「local はラダーを予測しない」の再解釈でもある。
予測しなかったのではなく、**測っていた対象が違った**。

実ラダーの遭遇シェア（v045 n=136 実測）で重み付けした6アーキタイプ。

## 6. ENC_V4 実装（進行中）

観測オブジェクトの全フィールドとエンコーダの読み取り箇所を突き合わせ、2つの穴を特定:

- **`obs.select` がエンコーダに一切入っていなかった**。デコーダは候補特徴に使っているが、
  **局面表現には「いま何を訊かれているか」が無い**。「どこにエネルギーを付けるか」と
  「何をベンチに出すか」と「ダメカンを何個置くか」で局面ベクトルが同一になる。
  デコーダ入力を持たない価値ヘッドは、この区別ができない。
  `remainDamageCounter` / `remainEnergyCost`（解決途中の残量）は**どこにも存在しなかった**。
- **`obs.logs` はコードベース全体で未使用**。前回の選択以降のイベント（ログ種別、コインの表裏、
  ダメージ値、行動主体別のカードID）。捨て札は「何が積まれたか」を示すが「**いま何が起きたか**」は示さない。

意図的に外したもの: logs の `attackId`。出荷側は `all_attack()` 失敗時に `attack_count=400` へ
フォールバックするので、エンコーダをそこに依存させると**新しい静かな train/ship 乖離**を作る。

検証: 最大インデックス 35720 / 38000、28語で安定。**train と ship の特徴ベクトルが
実局面300件で index・value・offset とも完全一致**（`parity_enc.py` を新設）。
ENC_V3 では tar レベルの確認しかしておらず、その下の層＝特徴ベクトル自体の一致は見ていなかった。

コーパス **4,062,285決定 / 46,657試合 / 16日**（12.0GB）。教師 V4T 学習中。
