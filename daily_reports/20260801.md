## 3. 出荷コードの監査で見つけたもの

定数をいじっても動かないので、出荷している `main.py` を読み直しました。

### (a) 最終手の選び方が訪問数で、同数なら候補の並び順 ← 本命

```python
if child.node is not None and max_visit < child.node.visit:
```

厳密比較なので、同数のときは `enumerate_candidates` が返した順で先頭が勝ちます。
AlphaZero が訪問数を使うのは数千回回すからで、sc16 で候補6手なら同数は頻繁に起きます。

軽微だろうと書きましたが、見誤っていました。

### (b) 探索が相手デッキを自デッキと仮定している ← 空振り

```python
sel = mcts_agent(obs_dict, my_deck, MODEL, _sc, opp_deck=my_deck)
```

`determinize()` は相手の伏せ札を `opp_deck` から引きます。ラダーの Grimmsnarl（オーロンゲ）は 46.5% なので、
残り 53.5% では相手が持っていないカードを相手の手札に置いて読んでいることになります。

正解デッキを渡した版と比べました（n=200）。

```
Alakazam（フーディン）      0.885 対 0.845   +0.040
Crustle（イワパレス）       0.735 対 0.770   -0.035
Mega Lucario ex           0.525 対 0.495   +0.030
                                   標準誤差 ±0.050
```

重み付きで +0.011。誤差の中です。**相手デッキの推定は作らなくてよい**という結論で、半日で閉じられました。

### (c) 時間予算の単価計算がずれている ← 軽微、修正済み

```python
per_sim = spent / max(1.0, acts * SEARCH_COUNT)
```

分母が実際に使った `_sc` でなく上限の 16 固定でした。時間が減って `_sc` が 8 に落ちた後、
1シミュレーションの単価を半分に見積もり、性急に 16 へ戻そうとします。上限で頭打ちになるので
事故にはなりませんが、実シミュレーション数を数えるように直しました。

## 6. 教師データに Grimmsnarl 席しか入っていない（着手中）

`build_multi.py:102`

```python
if archetype(decks[s], byid) != target:
    continue
```

コーパスに記録されるのは Grimmsnarl を使っている席の決定だけで、相手側の席は捨てています。
一方でエンコーダは手番プレイヤーの視点で特徴を作り、MCTS は相手ノードでも同じネットを呼びます。
つまり**ネットは「Alakazam 使いの視点から見た局面」を学習で一度も見ていないのに、
木のおよそ半分でそれを判定させられています。**
