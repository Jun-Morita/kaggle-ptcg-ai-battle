v3 の誤りを分解したところ、v2 で足した攻撃ダメージでも解消しない偏りが残っていた。

```
誤り 0.262（MAIN 52.3% + TO_HAND 21.7% で全体の74%）

              誤って上位に   誤って落とす      比
ABILITY           2413          1655      1.46 : 1   特性を使いすぎ

END                 36           160      1 : 4.44   ターンを終えない

```

**モデルは「このターンに既に何回使ったか」を見られなかった。** 直前3手しか持っていないため、
ターンの8手目を決める時点で「もう2回ダメカンを動かした」と「まだ何もしていない」を区別できない。

追加した9個（ターン単位の行動履歴＋ダメカン系）:

```
turn_actions_so_far / turn_abilities_used / turn_plays_used
turn_attaches_used / turn_evolves_used
opt_src_acted_this_turn / opt_same_action_this_turn
opt_counters_to_ko / opt_tgt_hp_ratio
```

作業中に2件の欠陥を発見して修正した。

1. **ダメカン系の対象解決が効いていなかった。** `inPlayArea` 経由でしか対象を引いておらず、
   DAMAGE_COUNTER 文脈は `area` + `playerIndex` で対象を指すため、**追加した特徴量が全て 0**
   になっていた。`semantic()` と同じフォールバックを入れて修正。
2. **`remainDamageCounter` はリプレイ観測では常に 0。** これを使う「カウンターが足りるか」の
   フラグは一度も発火しない。木が自力で作れない比率（対象の残HP割合）に差し替えた。

### (2) 探索を実装 — 検証付き上書き

MCTS の全面移植ではなく、**v013 の upside-only gate / v014 の turn-beam と同じ設計**を採った。

```
1. GBDT で全選択肢を採点し、上位M個の候補手を作る（部分集合の全列挙はしない）
2. 各候補について determinize したエンジンで手を適用し、
   自分のターンが終わるまで GBDT で貪欲に打ち切る
3. 到達局面を価値モデルで評価する
4. 方策の第1候補を MARGIN 以上上回るときだけ上書きする
```

理由: MCTS は実装面積が大きく、**今日だけで静かに劣化する不具合が3件**出た経路である。
方策を主役に置き、先読みは確認にだけ使う設計なら、壊れても方策の答えに戻るだけで済む。

配線の動作確認済み: **26ミリ秒/決定**（determinize / search_begin / search_step / search_end
すべて機能）。1試合600秒の予算に対して桁違いに軽い。

価値関数は**学習モデル**にする。ロールアウトは1回0.2秒で1手25回しか回せないが、決定木なら
数マイクロ秒で3桁多く評価できる。そのため**負けた側を含む両席コーパス**を初めて作った
（`build_value.py`）。従来のコーパスは勝者のみで、価値の学習信号が無かった。

学習分布の偏りは記録しておく: 負けの行は**ミラー戦に偏る**（両席が我々のデッキを持つのは
ミラーだけ）。ラベルは最終結果なので、強いパイロットが打ち切った互角局面も 1 になる。
探索は兄弟局面の順序さえ合えば良いので単調変形には耐えるが、**絶対値は勝率ではない**。
