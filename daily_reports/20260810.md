## exp085: 教師強度の「条件付け」— 棄却

### 設計

v055 の `>=1075` フィルタは、昨日、日付バイアスを持つことが分かっていた。ラダー全体の
スコア水準が下がったため、絶対値の閾値は日付が新しいほど厳しく効く。

```
07-26  2183 seats  >=1075 1686 (77%)
08-06  1137 seats  >=1075  289 (25%)
08-08   767 seats  >=1075  223 (29%)
```

つまり「上位層のみ」のつもりが「7月下旬を選ぶフィルタ」だった。そこで、データを捨てる
フィルタをやめ、**教師の強さを特徴量として渡す**形にした。

```
teacher_pct   その決定を打った教師の、その日の中での順位（0〜1）
              訓練時: 実際のパーセンタイル   推論時: 1.0（その日のトップとして打つ）
```

日別パーセンタイルにしたのが要点で、スコア水準の下落を自動で吸収する。実装は
`feats.py` にモジュール変数を1つ置き既定値を 1.0 にしただけなので、**推論側の改造が不要**。

### 訂正

昨日「held-out はコーパス末尾10%なので最新データ」と書いたが誤り。日ごとの seat を
交互に並べる実装（`zip_longest`）なので、末尾は最新の日ではなく seat 数の多い日が集まる。
held-out は時系列分割になっていない。判断はすべて直接対戦で行っているので結論は変わらないが、
held-out を「最新環境での精度」と読むことはできない。

この交互配置のため、既存コーパスを切って直近だけ取り出すこともできない（別ビルドが必要）。
