# exp084 — 公開エージェント（tetsutani）を物差しとして使う試み

## 動機

ローカルのゲートがラダー順を再現できない状態が続いていた（ルールベース6種、学習済み
Alakazam パイロット、自己対決の3種すべて不一致、うち1つは符号が逆）。
公開エージェント tetsutani は**デッキが我々と60枚完全一致**で、当時ラダー 911.3。
差は操縦だけなので、これを相手にすれば同じ問いをローカルとラダーで揃えられると考えた。

ライセンス上ローカル解析専用。`ref_tetsutani*/` は gitignore、再配布しない。
取り込んだ知見は自前で再実装する。

## 結果: 物差しとしては失格

対戦（n=120、`eval_vs_ref.py`）:

| ネット | ラダー実測 | 参照エージェント相手 |
|---|---:|---:|
| v3s | 884.5 / 860.9 → 873 | 0.325 |
| d28s | 805.3 / 805.2 → 803 | **0.467** |
| v15s | 744.7 | 0.392 |
| v4s (ENC_V4) | 未提出 | 0.492 |
| d28ms (他席データ) | 未提出 | 0.308 |

**ラダーで70点下の d28s が上に出る**（差の z ≈ +2.2）。順位相関が壊れている。
探索は sc=16 の固定回数で時間予算ではないため、並列実行の負荷では説明できない。

## 判断の局在化も否定された

`defer_ref.py` — 我々が運転し、指定した SelectContext だけ参照の答えに差し替える。
`--defer all` = 0.492 でハーネス自体は健全（ミラー戦なので、後述のとおりこの検証は不十分）。

| 委譲した context | 勝率（基準 0.325） |
|---|---:|
| TO_HAND | 0.258 |
| ATTACH_TO 系 | 0.375 |
| DAMAGE_COUNTER 系 | 0.283 |
| TO_BENCH/SETUP 系 | 0.317 |

どれも 0.5 に近づかない。66点差は「特定のルール抜け」ではなく方針の一貫性の差。

## 副産物1: フィールドゲートに参照を通す（`gate_field_ref.py`）

| セル | 我々 v3s | 参照 911.3 |
|---|---:|---:|
| Grimmsnarl ミラー | 0.970 | 0.983 |
| Alakazam | 0.810 | 0.900 |
| Archaludon | 0.710 | 0.700 |
| Crustle | 0.485 | 0.567 |
| lucario_v2 | 0.400 | 0.600 |

重み付き合計は参照 0.823 対 我々 0.770（+0.053）で**向きは正しい**。
ただし d28s も同じ +0.05 を出してラダーで70点落ちたので、合計値は使えない。

## 副産物2: lucario_v2 の「穴」は幻だった

per-cell 差が最大（+0.20）だったので `diff_lucario.py` / `defer_lucario.py` で追った。
DAMAGE_COUNTER の不一致率は 0.755（参照ノートブックの看板がダメージ移し替え制御）
と非常に高かったが、**委ねると勝率が下がる**（基準 0.573 → 0.480）。
`--defer all`（参照が我々の席を全部運転）も 0.510 で、n=60 の 0.600 は上振れだった。

## 【重要】この実験の物差し検証は不十分だった

`--defer all = 0.492` でハーネスを検証したつもりだったが、**あれはミラー戦（両席同じデッキ）
なので、デッキと席の取り違えは原理的に見えない**。exp085 で同型のループ（`eval_gbdt.py`）が
実際に壊れていたことが判明し、`harness.run_gauntlet` との差が 0.480 対 0.120 だった。

exp084 の対戦数値も同じ自前ドライバ系統なので、**絶対値は信用しない**。
ただし上の結論（順位相関が壊れている／判断は局在しない／lucario は穴でない）は
いずれも同一ドライバ内の相対比較なので、方向としては維持する。

以後の対戦は `harness.run_gauntlet` ＋ 出荷tar直接でのみ測る。

## 参照エージェントの構造（08-04 更新版 v25、当時 864.4）

以前「純粋な手書きルール」と記録したのは誤り。中核は**勾配ブースティング決定木**:

```
models/policy_ensemble.bin.gz  180KB  独自バイナリ "PTC2"
  main 396木 / c7 423木 / mid 429木 / low 58木 / easy 9木
  特徴量256個（カテゴリカル72）。選択肢1つずつを採点し上位k個。
  semantic_dup_count / semantic_dup_rank で「同じカードの何枚目か」を明示。
  推論は struct.unpack の純Python。
その上に matchup_router → human_controller → advisor_guard → residual_guard
→ tactical_guard → development_guard の6段が合法性を確認しつつ上書き。
```

この観察が exp085（自前の決定木ランカー）の出発点になった。
